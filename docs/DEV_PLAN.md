## 1. 技术选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 运行环境 | **Node.js ≥ 22 LTS** | 已确认。Windows / macOS 一键安装，自带 npm。 |
| 本地服务 | **纯 JavaScript（ES Modules），只用 Node 内置模块**（`http`、`fs`、`path`、`child_process`） | 服务端**零第三方依赖**：普通用户解压后不用跑 `npm install` 就能启动。 |
| 前端语言 | **TypeScript** | 计费、时间计算容易出错，类型检查能挡住一大类 bug。 |
| 前端框架 | **Preact + @preact/signals** | 体积约 4KB，写法和 React 一样；signals 适合「每秒都在变」的数字。 |
| 构建 | **Vite** | 把前端打包成静态文件放进 `app/`，由本地服务直接托管。 |
| 日历解析 | **ical.js**（Mozilla 出品） | 完整支持 RRULE、EXDATE、RECURRENCE-ID、VTIMEZONE，比自己写可靠。 |
| 解压 zip | **fflate** | Google 导出的是 `.zip`；fflate 体积小、纯 JS。 |
| 样式 | 原生 CSS + CSS 变量 | 设计稿里的设计变量直接写成 CSS 变量，只有浅色主题（已取消夜间主题）。 |
| 测试 | **Vitest**（核心逻辑）+ **node:test**（服务端）+ 浏览器手动验收清单 | 核心逻辑全部是纯函数，可以把「当前时间」当参数传进去，测试不依赖真实时钟。 |
| 字体 | 自带 woff2 文件（开源 OFL 字体），中文用系统字体 | 不依赖网络 CDN；中文字库太大，不打包。 |

- `src/core/` 只放纯函数：输入数据 + 当前时间 `now`，输出结果。所有计费、时间逻辑都在这里，并且都有单元测试。

## 3. 数据存储设计

### 3.1 文件
```
data/
├─ config.json        # 设置、学年、学费池、课程、日历源信息
├─ marks.json         # 课节标记（停课 / 翘课 / 迟到）+ 手动添加的课节
├─ slacks.json        # 摸鱼记录
├─ calendars/
│  └─ <sourceId>.ics  # 导入的日历原文（保留原文，规则改进后可以重新解析）
└─ backups/
   └─ 20261111-213000_config.json   # 每次写入前备份，每种文件保留最近 20 份
```
每个 JSON 文件都带 `schemaVersion`（以后数据结构变了，用它做升级迁移）和 `rev`（修改版本号）。

### 3.2 为什么存日历原文，而不是存展开后的课节
- 课节是由「日历原文 + 学年设置」算出来的，存原文就不会出现「两份数据不一致」。
- 以后课程识别规则改进了，重新解析一遍就行。
- 用户的标记（翘课等）按课节 ID 存，课节 ID = `事件UID | 原始开始时间`，重新导入、重新解析后 ID 不变，标记不会丢。

### 3.3 本地服务 API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 返回 `{ app: "tuition-ticker", version }`，用于单实例检测 |
| GET | `/api/data` | 一次性返回 config、marks、slacks、所有日历原文（数据量很小） |
| PUT | `/api/docs/:name` | 整份替换 `config` / `marks` / `slacks`；请求带 `rev`，和服务器上的不一致就返回 409（防止两个标签页互相覆盖） |
| POST | `/api/calendars` | 上传一个日历（`.ics` 文本，zip 在前端解开后逐个上传） |
| DELETE | `/api/calendars/:id` | 删除日历源 |
| POST | `/api/calendars/:id/sync` | 让服务去下载订阅链接（P4） |
| GET | `/api/export` / POST `/api/import` | 整体导出 / 导入备份（P4） |

**写入方式（防止文件写坏）**：先写到 `xxx.json.tmp`，再重命名覆盖原文件。重命名是原子操作，断电或崩溃时不会留下半个文件。

**安全措施**
1. 只监听 `127.0.0.1`，局域网其他设备访问不到；这样 Windows 防火墙也不会弹窗。
2. 校验 `Host` 头只能是 `127.0.0.1:端口` 或 `localhost:端口`（防止 DNS 重绑定攻击）。
3. 所有写操作必须带自定义请求头 `X-Tuition-Ticker: 1`。其他网站的页面发不出带这个头的请求（浏览器会先发预检请求，服务不放行），所以恶意网页无法篡改你的数据。
4. 请求体最大 5MB；订阅链接只允许 http/https，15 秒超时，最大 5MB，内容必须以 `BEGIN:VCALENDAR` 开头。

## 4. 核心算法（P1 阶段实现，这里先写清楚做法）

### 4.1 日历解析与展开（`core/ics/`）
1. **解压**：文件名以 `.zip` 结尾 → 用 fflate 解开，取出所有 `.ics`。
2. **解析**：`ICAL.parse(text)` → 拿到 `VCALENDAR`。先把里面所有 `VTIMEZONE` 注册到 `ICAL.TimezoneService`，这样 `TZID=Asia/Hong_Kong` 之类的时间才能正确换算。
3. **按 UID 分组**：同一个 UID 里，没有 `RECURRENCE-ID` 的是「主事件」，有的是「某一次的例外」（比如某周改了时间）。用 `event.relateException(例外)` 挂到主事件上。
4. **展开**：主事件有 `RRULE` 就用 `event.iterator()` 逐次迭代，直到学年结束；`EXDATE` 由 ical.js 自动跳过；每一次用 `event.getOccurrenceDetails(time)` 拿到「套用例外后」的真实开始 / 结束时间。
5. **过滤**：全天事件（`DTSTART;VALUE=DATE`）跳过；`STATUS:CANCELLED` 的那一次跳过。
6. **输出**：`Session { id, uid, title, location, startMs, endMs }`，时间统一存为 UTC 毫秒数；显示时再用 `Intl.DateTimeFormat` 转成本地时间。
7. 没写时区的「浮动时间」→ 按电脑当前时区处理。

### 4.2 课程识别（`core/courses.ts`）
1. 标题标准化：去首尾空格、合并多个空格。
2. 用正则提取课程代码：`/\b[A-Z]{2,5}\s?\d{3,5}[A-Z]?\b/`（如 `MFIN7001`、`COMP 3230`）。
3. 分组：有课程代码的按代码分组（这样同一门课的 Lecture 和 Tutorial 会自动合到一起），没有的按标准化后的标题分组。
4. 每组给出「建议是不是课」：
   - 建议勾选：重复 ≥ 4 次，单次时长 45 分钟到 4 小时。
   - 建议不勾：标题含 exam / quiz / deadline / due / holiday / reading week / office hour / 考试 / 假期 等。
5. 用户在识别页里确认、合并、改名、设学分；结果存为 `Course { id, code, name, credits, color, match: { codes[], titles[] } }`。以后重新导入时按 `match` 自动归类。

### 4.3 学年与学期（`core/academic.ts`）
- 配置：`{ yearStart: "08-01", splitDate: "12-25", billingPeriod: "semester" | "year" }`。
- **归属学年**：课节开始时间落在哪个「学年起始日 → 下一年学年起始日」区间。
- **归属学期**：在该学年内，早于分割日 → 上学期；否则 → 下学期。分割日的月份早于学年起始月时，分割日属于学年的下一个自然年（如学年 2026-08-01 开始，分割日就是 2026-12-25；南半球学年 2027-01-01 开始，分割日就是 2027-07-01）。
- **分割日检查**：把学年内所有课节按时间排序，找出相邻两节课之间最长的空档。如果分割日不在这个空档内，就建议把分割日改到空档的中间那天。

### 4.4 计费（`core/billing.ts`）
1. **学费池**：按学期计费 → 每个（学年, 学期）一个池；按学年计费 → 每个学年一个池。
2. 学费以「分」为单位存整数（HK$398,000 存为 39800000），避免小数精度问题。
3. **单价**：
   - 时长均摊：`rate = 池学费 / 池内所有计划课节总秒数`（停课、翘课的课节也算在分母里，见 PRD §3.4）。
   - 学分加权：先按学分把池学费分给每门课，再在每门课内部按时长均摊。
4. **预计算**：每个池内的课节按开始时间排序，算出每节成本和「截至每节结束的累计成本」（前缀和）。
5. **查询某一时刻**：用二分查找定位到 `now` 落在哪节课或哪两节课之间，历史消耗 = 前缀和 + 当前这节已过时间 × 单价。每次都从头算，不靠「每秒加一点」，所以永远不会累积误差，电脑睡眠唤醒后也立即正确。
6. **收尾校正**：池里最后一节课结束后，消耗直接等于学费总额（消除浮点尾差）。

### 4.5 上课状态机（`core/status.ts`）
`getStatus(now, sessions) → { kind, current?, next?, prev?, today[] }`，`kind` 取值：
`before-term`（学期未开始）/ `in-class`（上课中）/ `break`（课间，今天还有课）/ `done-today`（今天已下课）/ `no-class-today`（今天没课）/ `after-term`（学期已结束）。
- 两节课时间重叠：优先显示用户没有标记「翘课」的那节；都没标记就显示先开始的那节，界面上给出切换按钮。
- 纯函数，测试里传入任意 `now` 就能验证每种状态。

### 4.6 摸鱼（`core/slack.ts`）
- 点「我要摸鱼」：立即在 `slacks.json` 里写一条 `{ id, sessionId, startMs }`（先存再显示，这样中途关掉网页也不会丢）。
- 摸鱼金额 = 单价 × 摸鱼区间与课节区间的重叠秒数。
- 点「继续听课」：写入 `endMs`。
- 自动结束：如果检测到当前时间已经过了课节结束时间（包括网页关着的情况，下次打开时检测），把 `endMs` 设为课节结束时间。

### 4.7 货币、等价物与文案
- `money.ts`：内置 7 种货币的符号（HK$、¥、US$、£、€、C$、A$）和对美元的固定汇率表（带更新日期）；`convert(amount, from, to)`；`format(amount, currency)` 固定两位小数、千分位分隔。
- `equivalents.ts`：物价包里每项是 `{ name, emoji, price, currency }`。全部换算成当前币种后从便宜到贵排序；摸鱼时显示「不超过当前金额的最贵那一项」，以及能买几个。
- `copy.ts`：模板写法如 `"你发呆的{minutes}分钟，够买{count}{unit}{item}了"`；文案库按强度分三档（温和 / 正常 / 焦虑拉满）和场景分组（上课中 / 摸鱼中 / 课间 / 下课结算）；每 8 秒随机换一条，不重复上一条。

### P1 核心计算引擎

**目标**：`src/core/` 全部实现并测试；用你的真实日历跑出一份结果，你人工核对没问题。

| 任务 | 怎么做 |
|---|---|
| 构造测试日历 | 在 `tests/fixtures/` 手写若干小 `.ics`，每个覆盖一种情况：每周重复、`EXDATE` 跳过公众假期、`RECURRENCE-ID` 改时间、跨时区（伦敦夏令时切换周）、全天事件、`STATUS:CANCELLED`、两节课重叠、跨午夜、课程代码 Lecture + Tutorial |
| 实现 `ics/`、`courses.ts`、`academic.ts`、`billing.ts`、`status.ts`、`slack.ts`、`money.ts`、`equivalents.ts`、`copy.ts` | 按第 4 节的做法实现 |
| 单元测试 | 每个模块都测；重点测计费不变式：① 任意时刻 已消耗 + 剩余 = 学费；② 学期结束时已消耗 = 学费；③ 原版截图的数字能复现（每秒 0.3685，3 小时一节 ≈ 3,980） |

### P2 界面设计（Claude Design）

**目标**：拿到一套你确认过的设计稿，并把设计变量落到代码里。可以和 P1 同时进行。

**怎么做**
1. 用 Claude 里的 Design 功能（Artifact 工具，`quickstart` 选 design → 新建 Design 类型的 Artifact）。会先列出你账号下可用的 Design System：选一个现有的，或者不用现成的、直接按 PRD §7.1 的风格做。
2. 设计这些画面（仅浅色）：
   1. 首次启动引导（7 步：学校与地区 → 学期 / 学年 → 币种与学费 → 学年起始日与分割日 → 导入日历 → 识别课程 → 预览确认）
   2. 课程识别页
   3. 主界面：上课中
   4. 主界面：课间 / 今天没课 / 学期未开始

### P3 MVP 前端（PRD 的 P0 功能）

**目标**：从首次启动到日常使用全流程能跑通：导入你的日历 → 到上课时间自动计价 → 摸鱼 → 标记翘课。

| 任务 | 怎么做 |
|---|---|
| 状态与数据同步 | `state/` 用 signals 存 config、marks、slacks、日历原文；启动时 `GET /api/data`；修改后防抖 500ms 再 `PUT`；收到 409 时重新拉取并提示「数据在别的标签页被改过，已刷新」 |
| 派生数据 | 日历原文 + config → 课节列表 → 学费池和单价：用 `computed` 缓存，只在数据变化时重算；当前时间相关的数字每帧从缓存结果里查（二分查找，很快） |
| 首次启动引导 | 7 步向导（同 P2 设计）。第 5 步支持拖入 `.zip` / `.ics`；第 6 步就是课程识别页；第 7 步预览「共 M 节、X 小时、每秒成本 r、每节平均 y」，以及分割日检查结果。引导结束前不允许学费为空 |
| 「当前时间」 | 全局一个 `now` signal：前台每帧（`requestAnimationFrame`）更新；标签页在后台时改成每秒一次；从后台切回前台（`visibilitychange`）时立即更新 |
| 跳动的大数字 | `TickingNumber` 组件直接改 DOM 里的文字（不走整页重新渲染），使用等宽数字，避免每帧都触发布局变化导致卡顿 |
| 主界面 | 按状态机的 6 种状态显示不同内容（PRD §5.1、§7.2）：本节消耗、单价、已上 / 剩余时长、第 i/N 节、学期学费油箱、轮播文案、摸鱼按钮 |
| 摸鱼页 | 全屏覆盖；实时金额 + 等价物提示；背景光斑用纯 CSS 动画；「继续听课」→ 结算卡 |
| 课节列表 | 按周列出所有课节；点开某节可标记「停课 / 翘课」；过去的课节显示消耗和摸鱼情况 |
| 设置页（基础） | 修改学费、币种、学年起始日、分割日、计费周期；重新导入日历；修改后预览新单价并确认 |
| 演示模式 | 内置一份虚构课表（伪造当前时间正好在上课），没导入日历也能看到效果 |
| 标签页标题 | 上课中显示「HK$2,687 · MFIN7001」，摸鱼中显示「🐟 HK$3.51」 |

**验收**（用你的真实日历 + 浏览器实际操作）
- [ ] 首次启动走完引导，数字和 P1 的 `inspect-calendar` 结果一致。
- [ ] 把系统时间调到某节课中间（或在开发模式里用 `?now=2026-11-12T10:30` 参数伪造时间）→ 自动显示「上课中」，数字正确。
- [ ] 摸鱼开始 → 关掉网页 → 重新打开，摸鱼状态还在；过了下课时间自动结束。
- [ ] 标记翘课后，翘课损失统计正确，已消耗 + 剩余仍等于学费。
- [ ] 后台标签页放一小时，CPU 占用接近 0；切回来数字立即正确。

### P4 第一个公开版本的功能（PRD 的 P1 功能）

按价值从高到低排序，每项可以单独开发、单独验收：

| 功能 | 怎么做 |
|---|---|
| iCal 订阅链接同步 | 服务端 `calendar-sync.js` 用 Node 自带的 `fetch` 下载（含安全限制）；启动时同步一次，之后每 6 小时一次；前端显示「上次同步：x 分钟前」和「立即同步」按钮；同步后单价有变化时提示 |

| 翘课计算器 | 课节详情里显示「翘掉这节 = 扔掉 HK$3,980 ≈ 88 盒三餸饭」 |
| 上课 / 下课提醒 | `localhost` 属于浏览器认可的安全环境，可以用 Notification API；网页开着时，课前 N 分钟和下课时弹系统通知；用户拒绝授权就只在页面内提示 |

| 主题 | 只有浅色主题（夜间主题已取消） |

| 迟到 / 早退标记 | 课节详情里填分钟数 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 学校导出的日历格式有特殊情况 | 用 ical.js 处理标准规则；真实日历纳入测试；保留日历原文，修复规则后可以重新解析 |
| Windows 命令行中文乱码 | `chcp 65001` + 脚本文件存为 UTF-8；P0 阶段实测，如果仍有问题就把命令行提示改成英文 |
| 用户双击了两次 / 端口被占用 | 单实例检测 + 自动换端口 |
| 两个标签页同时修改数据 | `rev` 版本号冲突检测 |
| 数据文件损坏 | 原子写入 + 自动备份 |
| 设计稿与实现差距大 | P2 先定设计变量，P3 组件全部使用这些变量；每个页面做完都和设计稿对比 |
| 别人的电脑没装 Node | 启动脚本检测并给出下载指引；README 第一步就写 |
